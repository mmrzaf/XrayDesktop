# Phase 4 — desktop UX and packaging

Source preview `0.1.0-preview.4`; Xray baseline v26.11.9; Windows x64, .NET SDK 10.0.404. This is a source implementation record. Windows compilation, mandatory executable checks, native proxy mutation, real-core connectivity, clean-machine testing and interactive GUI acceptance have **not been executed** in the authoring environment. The Phase 0–3 records remain historical; do not treat them as passed tests.

## User experience

- Connection, Logs, Diagnostics and Settings are separate native WinForms tabs. Global process status, Windows LAN proxy state and cancellation remain visible. Connection and settings pages have scrollable layouts; diagnostic options and the results table scroll independently. The forms use DPI scaling (PerMonitorV2 at application level), standard controls, system colors and normal keyboard navigation. The main window's nominal minimum is 620 × 460 logical pixels. Actual DPI behavior requires manual verification.
- A notification-area icon is available for the lifetime of the displayed app. Double-click or Show window reopens it. Start, Stop, Enable system proxy and Restore system proxy use the same serialized commands and state as the main form. The tray tooltip distinguishes core state from LAN proxy state, not internet connectivity. Tray commands restore/show the window so security prompts cannot silently run in the background. While busy, show the window to cancel; tray mutations and Exit are disabled until the operation finishes. Close is never interpreted as minimize.
- Minimize-to-tray is opt-in and becomes active after Save desktop preferences. Minimizing while a command is active leaves a taskbar window to avoid hiding possible confirmation dialogs. Exit and normal Close restore the proxy then stop the owned core through the existing workflow; unresolved restoration retains the encrypted journal and requires the established force-stop decision. Timer, tray icon and menu are disposed with the form. OS shutdown, force-kill and crashes still rely on next-launch recovery; no watchdog is included.
- All modal commands, including manual endpoint selection, raw log export and report preview, pass through the command gate. A read-only background proxy poll no longer toggles the busy UI; mutations and shutdown await any outstanding poll before proceeding. A child exit still invokes the recovery path; no continuous remote connectivity probe is introduced.
- Logs remain a bounded in-memory session buffer (5,000 lines and 2 MiB of UTF-16 character count including CRLF separators, not a byte-level disk limit). Auto-scroll can be toggled while operations run. When disabled, the GUI attempts to retain selection and caret; exact viewport preservation after retention eviction is not guaranteed. Copy and Save raw logs require explicit sensitive-data acknowledgement. The save is an atomic UTF-8 snapshot of the retained buffer, not a redacted report. No automatic disk recording or rotating raw log files is enabled; this is deliberately deferred to avoid unnecessary secret persistence. Use the existing allowlisted diagnostic report for sharing.

## Local preferences and clearing data

`data/desktop.json` (schema version 1, read limit 16 KiB) stores only minimize-to-tray, remember-window, log auto-scroll and optional normal window placement/maximized state. Defaults: tray minimization off, remember-window and auto-scroll on. `Save desktop preferences` explicitly saves behavior; normal exit updates placement only if remembering is enabled and the file was readable. Unreadable files are not automatically replaced on exit. Window placement is in Windows screen coordinates, clamped to a current working area by maximum intersection, with disconnected monitors falling back to centered placement on the primary monitor. Negative coordinates are supported. Very small work areas or unusual DPI transitions still need testing. If remember-window is disabled no bounds are stored.

`Reset preferences` explicitly resets desktop and diagnostic preferences (including in-memory direct/public-IP and enable-after-Start consent); the two files are independent atomic writes, not a cross-file transaction. If the second write fails the first may already be reset; the error is surfaced. `Clear profile list` clears selection and profile metadata only, requires the owned core to be stopped and confirms replacement of existing settings. It never deletes referenced configurations, managed profile copies, geodata, snapshots, logs exported by the user or DPAPI recovery data. Managed copies may be the only remaining copy of a profile. The user can manually remove private local files after stopping the core and reviewing the contents. No bulk filesystem deletion is introduced. This is the conservative interpretation of F10 clear-local-data.

The existing profile/diagnostic stores now distinguish absent files from I/O/access failures. Profile writes are validated and bounded to the same 1 MiB used by the reader; diagnostic writes respect their 16 KiB read limit. Invalid or oversized writes fail before atomic replacement. Existing profile edits and probe preference changes require their established explicit save/confirmation. Automatic enable-after-Start and direct network consent are intentionally not persisted. Manual endpoint selection is session-only. There is no automatic core startup. Existing storage is not migrated or combined into one file.

## Packaging and automated checks

- Pinned SDK, SHA-pinned GitHub Actions, zero external package references, Release build, warnings as errors and self-contained single-file Windows x64 publish are unchanged.
- `scripts/Build.ps1` produces `artifacts/phase4/dist/XrayDesktop-0.1.0-preview.4-win-x64.zip` and its external `.sha256` file. The ZIP contains only `XrayDesktop.exe`, `README.txt`, `examples/direct-test.json` and `SHA256SUMS.txt`. The existing deterministic entry order/timestamps, layout and hash checks and extracted-EXE smoke tests remain mandatory. No core binary, geodata, user settings or configuration is bundled. The payload is unsigned, and the archive hash is integrity evidence, not publisher authentication.
- 13 new mandatory console checks (76 cumulative) cover safe defaults, round trips, corrupt and oversized preference retention, invalid save refusal, placement on negative/disconnected/partially visible/small monitors, profile settings size enforcement, reference clearing without deleting configuration bytes and log bounds including Windows line separators. Five existing published-EXE headless checks remain in the package pipeline. The actual test execution is pending.
- `XRAY_TEST_UI=1` is an additional opt-in STA smoke test. It constructs an invisible main form and HWND, checks the four tabs and disposes the form without calling Show or Close (which would run the real recovery logic). It does not start Xray, mutate Windows proxy or show the tray. The Actions workflow dispatch input `hidden_ui_check` enables this check; the default push/PR build does not require a GUI desktop. It is not an interactive or DPI acceptance test. The existing opt-in real core and WinINet read checks are unchanged.

## A14/A16 Windows acceptance checklist

Record the actual OS build, exact app/core versions, screen resolutions/scaling, whether the app is non-admin, test date and outcome. Use a disposable Windows account/VM for any native proxy writes. Keep private configurations out of CI and logs out of reports. Each item below is **pending** until performed.

| Check | Procedure and expected result |
|---|---|
| Clean CI | Push this exact revision; inspect mandatory checks, extracted-EXE exit codes and artifact hashes. No warnings or skipped mandatory steps. |
| Clean Windows | Extract into a writable private path with spaces and non-ASCII characters on a supported Windows 11 x64 machine without a separately installed .NET runtime. Launch as a normal user; no elevation. Verify adjacent `xray.exe` and assets found after changing launch working directory. |
| Missing/bad core | Without `xray.exe`, startup recovery still runs; dismiss core error and use editor/settings. A wrong core version requires confirmation, never automatic download. |
| Screen scaling | At 100%, 150% and 200% DPI, resize to nominal minimum and maximize; all commands reachable by scrolling, text readable, no clipped confirmation dialog, global status and Cancel visible. Move between monitors of different DPI; inspect controls and list view. |
| Placement | Save placement, restart; repeat maximized, negative coordinate monitor, disconnect monitor and restart. Window appears on a current screen. Disable remembering, save, close, check no placement persisted. |
| Keyboard | Use Tab/Shift+Tab, space/Enter and arrow keys; navigate tabs, profile and endpoint selection, run controls, dialogs, cancel. Check high-contrast/system colors. |
| Tray defaults | Minimize with defaults: taskbar window remains, icon exists. Double-click or Show; start/stop and enable/restore mirror main controls and prompt visibly. |
| Tray opt-in | Save minimize preference, minimize idle, verify window hidden but core continues and icon reopens it. Close and tray Exit restore proxy then stop; exit removes icon. No automatic start at next launch. |
| Busy behavior | Minimize during validation/diagnostics; owner remains available. Start/Stop/Enable/Restore from tray disabled while busy. Show and cancel; inspect logs. Proxy polling does not reset text field focus. |
| Exit failures | With a simulated external proxy conflict or native restoration failure, invoke Stop, Close and tray Exit; verify no blind overwrite, explicit keep-running/force-stop prompt and retained journal. Kill owned Xray while minimized and inspect recovery on reopening. Force-kill GUI in VM and reopen for recovery. |
| Logs | Generate bounded high-rate fixture logs; verify scroll toggle and responsiveness, clear buffer, cancel copy/save warning and confirm no exported file. Explicit save creates a private UTF-8 snapshot. No automatic log file appears. |
| Preferences | Test default settings, save/reload, corruption/oversize retention, explicit reset and interrupted/failing writes. Verify clearing profile references keeps both source and managed JSON bytes and never removes the journal. Verify no direct consent persists. |
| Diagnostics | Run local, HTTP, SOCKS, remote and direct test groups in appropriate profiles; cancel and inspect report preview. Verify scrolling at high DPI and no unapproved direct request. |
| Clean machine uninstall | Restore/stop/close first; then remove the portable folder after preserving wanted configs. Journal may exist outside folder only if unresolved; do not delete to mask a failed restore. |

## Remaining differences and limitations

- Optional speed probe, continuous monitoring, automatic rotating disk logs and optional redacted raw log excerpts remain deferred. Explicit raw export is intentionally separate from the safe diagnostic report. F10 is fulfilled only conservatively: profile metadata reset, preference reset and in-memory log clear are implemented; managed configuration copies and externally saved files are not bulk-deleted. Enable-on-start, manual endpoint and network consent remain transient.
- No code signing, no repository license selection, no native watchdog or TUN. The existing narrow process-creation/job-assignment crash window and non-atomic OS proxy comparison/write window remain documented risks. Windows 10 remains unverified. No claim is made that system proxy provides full VPN coverage.
- Phase 5 must begin with the real Windows build and mandatory test execution, address compiler/analyzer/test failures, complete A08–A17 including real private VLESS connection and native proxy restore/recovery, and record evidence before tagging a stable release. All acceptance criteria remain open; this preview is not a certified Windows executable.
